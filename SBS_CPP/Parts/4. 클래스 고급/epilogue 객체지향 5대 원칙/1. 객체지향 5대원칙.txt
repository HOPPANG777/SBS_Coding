=========================================================================================
1>	단일 책임 원칙
	( Single Responsiblity Principle, SRP )
=========================================================================================

	-	소프트웨어의 설계부품은
					( 클래스, 함수 등 )
		단 하나의 책임만을 가져야 함..
					( 기능 )
		 
		ㄴ	책임 영역이 명확해짐..

			ㄴ	수정, 편집에 대한 부작용이
				발생할 확률 감소..



=========================================================================================
2>	개방-폐쇄 원칙 ( Open-Closed Principle, OCP )
=========================================================================================

	-	소프트웨어의 구성요소는
					(컴포넌트, 클래스, 모듈, 함수)
		확장에는 열려있고,
				( open )
		변경에는 닫혀있어야 함..
				( close )

	-	변경될 수 있는 부분
		파악에 초점..

	-	
		==================================================
				변경 여부..		|	설계 방식..
		==================================================
			자주 변경될 수		|	수정하기 쉽게 설계..
			있는 부분..			|-------------------------
								|	의존관계, 또는
								|	상속을 통하여 구현..
								|-------------------------
								|	게임에 사용되는 컨텐츠
								|	-	총알, 적, npc 등..
		--------------------------------------------------
								|	수정되는 내용에 영향을
								|	받지 않도록 설계..
			변경되지			|-------------------------
			않아야할 부분..		|	추상 클래스 또는
								|	인터페이스로 분리..
								|-------------------------
								|	게임 시스템..
								|	-	게임 매니져,
								|		UI 매니져,
								|		스폰 기능 등..
		==================================================
		

	----------------
	상황..
	----------------

			class CSoundPlayer
			{
				public :
					void PlayWav()
					{
						cout<< "Wav Play" << endl;
					}
			}

			void main()
			{
				CSoundPlayer sPlayer;
				sPlayer.Play();
			}



	----------------
	문제 제기..
	----------------

		-	CSoundPlayer는 현재 wav 파일만
			재생가능..

		-	요청 발생!!!
			
			-	다른 포맷의 음원 파일
				재생 기능 추가..
			
				ㄴ	mp3나 그 외 음원파일..



	----------------
	고찰..
	----------------

		-	CSoundPlayer는 음원에 따라
			Play()함수가 다르게
			구현되어야 함..

			ㄴ	CSoundPlayer를 추상화..

			ㄴ	Play()함수를 추상 클래스
				또는 인터페이스로 분리..
		


	----------------
	해결.. 
	----------------


			class CSound
			{
				public :
					virtual void Play() = 0;
			}

			class CWav : public CSound
			{
				public:
					virtual void Play() { cout<< "Wav Play" << endl; }
			}

			class CMp3 : public CSound
			{	
				public:
					virtual void Play() { cout<< "Mp3 Play" << endl; }
			}

			class CFlac : public CSound
			{
				public:
					virtual void Play() { cout<< "FLAC Play" << endl; }
			}

			class CSoundPlayer
			{
				CSound* _pSound;

				public :
					void SetFile( CSound* pSound )	{ _pSound = pSound }
					void Play() { _pSound.Play(); }
			}


			void main()
			{
				CSoundPlayer sPlayer;

				sPlayer.SetFile( new CMps());
				sPlayer.Play();

				sPlayer.SetFile( new CWav());
				sPlayer.Play();

			}

3>	리스코프 치환 원칙..
=========================================================================================

	-	부모 클래스와 자식 클래스 사이의
		행위에는 일관성이 있어야 함..

		-	부모 클래스의 인스턴스 대신
			자식 클래스의 인스턴스를 사용해도
			문제가 없어야 함..


		-	예)
				도형 클래스,
				사각형 클래스,
				원 클래스가 있음...

				-	원과 사각형 클래스는 도형 클래스의
					상속을 받는다고 가정..
				
				도형 클래스 속성..
					(1) 둘레.
					(2) 넓이.
					(3) 각.

				자식 클래스로 교체 했을때도
				일관성이 있어야 함..
				
				사각형 클래스 속성..	-	일관성 유지..
					(1) 둘레	( O )
					(2) 넓이	( O )
					(3) 각		( O )


				원 클래스 속성..		-	원은 각이 없음..
											일관성 깨짐..
					(1) 둘레	( O )
					(2) 넓이	( O )
					(3) 각		( X )	<--	도형클래스는 리스코프를
											만족하지 않은 설계이므로
											수정 필요 !!

4>	인터페이스 분리 원칙..
=========================================================================================

	-	인터페이스란..
		[ 참고 : https://ko.wikipedia.org/wiki/%EC%9D%B8%ED%84%B0%ED%8E%98%EC%9D%B4%EC%8A%A4_(%EC%BB%B4%ED%93%A8%ED%8C%85) ]

		-	서로 다른 두 개의 시스템이나
			장치 사이에서 정보나 신호를
			주고받는 경우의 접점이나 경계면..

		-	상호작용이나 커뮤니케이션에
			필요한 매개체..


	-	클래스는 자신이 사용하지 않는
		인터페이스는 구현하지 말아야
		한다는 원칙..

		-	하나의 일반적인 인터페이스 보다
			여러 개의 구체적인 인터페이스가 나음..

		예)	스마트 폰에는 전화, 웹서핑, 사진 촬영 등
			여러가지 기능이 탑재되어 있음..
			전화 기능이 웹서핑, 사진 촬영등
			다른 기능을 사용하지 않음..

			ㄴ	전화, 웹서핑, 사진 촬영 기능은
				각각 독립된 인터페이스로 구현하여,
				서로에게 영향을 받지 않도록
				설계해야 함..

5>	의존성 역전 원칙..
=========================================================================================

	-	의존 관계를 맺을 때, 변화하기 쉬운것 보단
		( Has A )		
		변화하기 어려운 것에 의존해야 함..

		-	
			-------------------------------------------
			변하기 쉬운 것..	|	구체적인 것..
								|	실제 기능..
			-------------------------------------------
			변하기 어려운 것..	|	추상 적인 것..
								|	공통의 인터페이스..
								|	추상 클래스..
			-------------------------------------------

	-	자식 클래스에 수정이 필요한 경우,
		부모 클래스까지 변경해서는 안됨..

	-	구체적인 클래스보다
		인터페이스나 추상 클래스를 이용하여
		의존 관계를 구성할 것..

	-	참고 : https://defacto-standard.tistory.com/113

	-	CSoundPlayer 참고..

		-	SetFile 함수..

			-	실행하고자 하는 구체적 기능을
				바꿀수 있음..


		-	새로운 오디오 파일 포맷을 실행..
			(예 : FLAC)

			-	CSound를 상속받는 새로운 클래스를 만든후
				( CFlac )
				Play 함수를 구현..

			-	CFlac으로 인스턴스를 생성한 후
				CSoundPlayer의 인스턴스인
				sPlayer의 SetFile 함수로 연결..
