	사전 실습 )
	
		그 동안 배운 내용을 활용하여
		은행 계좌 관리 프로그램을
		만듭니다..

		-	계좌에 필요한 정보
			-	ID, 이름, 현재 보유금액..

		-	구현시 유의 사항
			-	c++을 기반으로
				작업..
			-	구조체, 배열 등을
				활용..
			-	헤더와 구현부로
				나눠서 작업..
		

		실행)
			----- Menu -----
			1. 계좌 개설
			2. 입 금
			3. 출 금
			4. 조 회
			5. 전체 조회
			6. 종 료


			1. 계좌 개설
				-	ID, 이름, 현재 보유금액을 설정..

			2. 입 금
				-	입금 하려는 계좌의
					ID를 검색한후
					해당 계좌의 보유금액에
					일정액을 추가..

			3. 출 금
				-	출금 하려는 계좌의
					ID를 검색한후
					해당 계좌의 보유금액에
					일정액을 차감..

			4. 조 회
				-	특정 ID로 검색하여
					계좌의 정보를 출력..

			5. 전체 조회
				-	현재 등록되어있는
					모든 계좌의 정보를 출력..

			6. 종 료
				-	프로그램을 종료..

1>	프로그래밍 패러다임..
	
	-	패러다임..

		ㄴ	한 시대의 보편적인
			사고의 틀이나 인식의 체계..
=================================================================

	----------------------
	1]	순차적 프로그래밍..
		( Sequential )
	----------------------

		1)	가장 초기에 등장한
			패러다임..

		2)	프로그램의 흐름이 코딩을 작성한
			흐름이나 순서에 기반하는
			프로그래밍 방식..

			예) gw basic..
				[ 참고 : https://www.clien.net/service/board/park/6387982 ]

		3)	구조라는 개념이 없어서
			goto와 같은 키워드로 코드의
			흐름을 제어..

		4)	단점..

			-	프로그램의 규모가 커질수록
				코드의 흐름 제어가 어려움..


	------------------------------------
	2]	절차적 ( Procedural ) 또는
		구조적 프로그래밍( Structured )..
	------------------------------------

		----------------------
		1)	절차적 프로그래밍..
		----------------------

			-	프로그램을 프로시져 단위로 나누고 
				프로시져들끼리의 호출을 통하여
				프로그램을 제어..

				ㄴ	프로시져..

					ㄴ	프로그램을 여러 개의 단위로
						분해한 것..

					ㄴ	함수와 유사..


		----------------------
		2)	구조적 프로그래밍..
		----------------------

			-	모듈을 단위로 프로그램을 나눠서
				제어하는 방식..

				ㄴ	모듈	..

					ㄴ	비슷한 기능을 처리하는 프로시져들을
						모아 소스 파일로 묶은 것..

				
		**	결국 비슷한 역할을 하는
			프로시져들을 묶어서 관리하는
			방식이므로 큰 범위에선 두 방식을
			같은 방식이라해도 무방..
			
			예)	C언어..


		3)	단점..

			-	특정 자료형과 해당 자료를 관리하는
				함수가 물리적으로는 같은 위치에 있을수 있지만,
				논리적으로 분리되어 있을수 있음..

				ㄴ	프로그램의 규모가 커질수록
					관리가 어려움..


	-----------------------
	3]	객체지향 프로그래밍..
	-----------------------

		1)	세상의 사물( 객체 )을 인식하는
			방식으로 프로그램을 설계하는 방식..

		2)	여러 독립적인 부품들의 조합,
			즉 객체들의 유기적인 협력과
			결합으로 문제를 해결해가는 패러다임..

			ㄴ	부품을 먼저 만든 뒤 그 부품들을
				조합해가는 방식..


		3)	단점..

			-	객체간의 관계에 대한 명확한
				이해가 필요..

				ㄴ	초기 설계 단계에
					많은 시간 필요!!!

			-	다중 상속을 적용할 경우
				작업이 어려워질 수 있음!!!


=========================================
2>	객체지향 프로그래밍..
	( Object Oriented Programming.. OOP )
=========================================

	--------------
	1]	주요 개념..
	--------------

		----------
		1)	객체..
		----------

			-	주변에 보이는 사물 또는
				사물에 비유하여
				표현 가능한 것들..

			-	[ 상태 ]와 [ 행위 ]를 지님..


		------------
		2)	클래스..
		------------

			-	객체의 타입 또는
				객체를 구성하는 틀..

			-	주로 붕어빵과 붕어빵틀에 비유..

				ㄴ	객체..
					ㄴ	붕어빵..

				ㄴ	클래스..
					ㄴ	붕어빵 틀..



	-------------------------
	2]	객체지향의 4가지 특징..
	-------------------------
	
		------------
		1)	추상화..
		------------

			-	공통의 속성이나 기능을
				하나로 묶는 것..


			-	작은 범위에서 큰 범위로
				개념을 정리하는 것..

				<-----> 일반화..


			-	중요한 부분을 강조하기 위해
				불필요한 세부 사항들은 제거하고
				가장 본질적이고 공통적인 부분만을
				추출하여 표현..

				==============================
					추상화	|	일반화
				------------------------------
					탈 것..	|	자동차, 비행기,
							|	오토바이, 배...
				==============================
	

		----------
		2)	상속..
		----------

			-	기존의 클래스를 재활용하여
				새로운 클래스를 작성하는 것..

			-	클래스 간의 공통되는 속성과 기능들을
				상위 클래스에 두고 해당 상위 클래스로부터
				확장된 여러 개의 하위 클래스들이
				간편하게 사용하도록 함..

			-	하위 클래스 입장에서 간편하게
				재사용 가능하며 반복적인 코드를
				최소화 가능..


		------------
		3)	다형성..
		------------

			-	어떤 객체의 속성이나 기능이
				상황에 따라 여러 가지 형태를
				가질 수 있는 성질..

			-	어떤 객체의 속성이나 기능이
				그 맥락에 따라 다른 역할을
				수행하는 것..

			-	같은 이름의 메서드가 상황에 따라
						( 멤버 함수 )
				다른 역할을 수행하는 것..

				ㄴ	일반적으로 추상화와
					상속을 통해 구현..


		------------
		4)	캡슐화..
		------------

			-	같은 책임 또는 역할을 가지는 
				데이터( 상태 )와 함수( 행위 )를
				하나로 묶어서 관리하는 것..


			-   주요 목적..

				ㄴ	데이터 보호..

					ㄴ	외부의 잘못된 사용으로 인해
						객체가 손상되지 않도록 방지..


				ㄴ	정보 은닉..

					ㄴ	내부의 동작을 감추고 
						외부에는 필요한 부분만 노출..

			----------
			-	특징..
			----------

				-	캡슐화된 객체의 세부내용은
					외부에 은폐..

					ㄴ	수정 또는 에러 발생시
						파급 효과가 적음..

				-	재사용에 용이..

				-	사용자 입장에서 각 객체들간의 메시지 전송시
					각 객체의 세부 내용은 알 필요가 없음..
					
					ㄴ	인터페이스가 단순해지고,
						객체간의 결합도가 낮아짐..
