	디자인 패턴

	----------
	1.	정의..
	----------

		-	소프트웨어 설계에서 공통으로
			발생하는 문제에 대해 자주 쓰이는
			설계 방법을 정리한 패턴..

			-	패턴..

				-	다양한 응용 소프트웨어 시스템들을
					개발할 때도 서로 간에 공통되는
					설계 문제가 존재하며
					이를 처리하는 해결책 사이에도
					공통점이 있는데 이러한 유사점을
					일컫는 말..


		-	“ 바퀴를 다시 발명하지 마라
			  ( Don't reinvent the wheel ) ”

			ㄴ	이미 만들어져서 잘 작동하는 것을
				처음부터 다시 만들 필요가 없다..




	-------------------------------------
	2.	GOF( Gang Of Four ) 디자인 패턴..
	-------------------------------------

		----------
		-	개념..
		----------

		-	에릭 감마, 리차드 헬름,
			랄프 존슨, 존 블리시디스..
			
		-	소프트웨어 개발 영역에서
			디자인 패턴을 구체화 하고
			체계화한 사람들..

		-	23가지의 디자인 패턴을 정리..

			-	크게 3가지 범주로 정리..

				-	생성( Creational )..
				-	구조( Structural )..
				-	행위( Behavioral )..



		----------
		-	분류..
		----------

			----------
			-	생성..
			----------

				1) Builder..

					-	생산 단계를 캡슐화 하여
						구축 공정을 동일하게 이용..


				2) Prototype..

					-	어떤 개체를 복사하여
						새 개체를 생성..


				3) Factory Method..

					-	객체를 생성하기 위한
						인터페이스를 정의하여
						어떤 클래스가 인스턴스화 될지를
						서브 클래스가 결정..


				4) Abstract Factory..

					-	생성군들을 하나의 그룹으로
						모아놓고 팩토리 중에서 선택..


				5) Singleton..

					-	유일한 하나의 인스턴스를
						보장..



			----------
			-	구조..
			----------

				1) Bridge..

					-	추상과 구현을 분리하여
						결합도를 낮춤..


				2) Decorator..

					-	소스를 변경하지 않고
						기능을 확장..


				3) Facade..

					-	하나의 인터페이스를 통해
						느슨한 결합을 제공..


				4) Flyweight..

					-	대량의 작은 객체들을
						공유..


				5) Proxy..

					-	대리인이 대신
						그 일을 처리..


				6) Composite..

					-	개별 객체와 복합 객체를
						클라이언트에서 동일하게 사용..


				7) Adapter..

					-	인터페이스가 달라서
						사용하지 못하는 클래스를
						함께 사용..



			----------
			-	행위..
			----------

				1) Interpreter..

					-	언어 규칙 클래스를
						이용..


				2) Template Method..

					-	알고리즘 골격의 구조를
						정의..


				3) Chain of Responsibility..

					-	객체들끼리 연결 고리를 만들어
						내부적으로 전달..


				4) Command..
					-	요청 자체를 캡슐화하여
						파라미터로 넘김..


				5) Iterator..

					-	내부 표현은 보여주지 않고
						순회..


				6) Mediator..

					-	객체 간 상호작용을
						캡슐화..


				7) Memento..

					-	상태 값을 미리
						저장했다가 복구..


				8) Observer..

					-	상태가 변할 때
						의존자들에게 알리고,
						자동으로 갱신..


				9) State..

					-	객체 내부 상태에 따라서
						행위를 변경..


				10) Strategy..

					-	다양한 알고리즘을 캡슐화하여
						알고리즘의 대체가 가능하게 함..


				11) Visitor..

					-	오퍼레이션을 별도의 클래스에
						새롭게 정의..
