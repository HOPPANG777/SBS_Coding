	----------------------------------------
	-	[ 1.MemBit / 1 - 화면에 직접 그리기 ]
		실행 후 고찰..
	----------------------------------------

		-	마우스 왼쪽 버튼을 클릭할 때마다
			WM_PAINT를 강제로 호출..

		-	WM_PAINT 이 호출될 때마다
			5000개의 원을 임의의 색, 위치,
			크기로 그려줌..

		-	마우스 왼쪽 버튼을 연속으로 클릭하면
			화면이 갱신되는데 종종 깜빡임이 발생..

			ㄴ	컴퓨터의 성능이 발달하여
				잘 눈에 띄지 않음..


	-------------------------------
	-	화면 깜빡임이 생기는 이유..
	-------------------------------

		-	[ InvalidateRect ] 호출할 때
			마지막 인수가 TRUE 인 경우,
			작업 영역 전체를 윈도우 클래스에
			등록된 배경 브러시로 초기화..


		-	이때, [ BeginPaint ] 호출 시
			[ WM_ERASEBKGND ]가 발생..

			-	[ InvalidateRect ]의 마지막 인수가
				[ FALSE ] 일때는 호출 안됨..

			-	[ DefWindowProc ]에서 처리를 함..

			-	[ return 0 ]가 아닌
				[ break ]로 종료해야함..

			  
		-	컴퓨터 처리 속도가 빠르다면
			눈에 띄질 않음..

			-	깜빡임이 사라지는 건 아니며
				깜빡임의 주파수가 높아질 뿐..


	---------------------
	-	깜빡임 해결 방법..
		참고 : [ 프로젝트 2. Bounce ]
	---------------------

		----------------------
		-	무효 영역 최소화..
		----------------------

			-	[ InvalidateRect ] 영역을
				최소화..


			-	장점..

				-	속도가 매우 빠름..


			-	단점..

				-	애니메이션 영역이 좁아야한다는
					제약이 생김..

				-	게임의 경우, 에니메이션이 적용되는
					객체가 화면 전 영역에 걸쳐 있으므로
					큰 의미가 없음..


		-------------------------
		-	원래 그림을 지우지 않고
			새로 그려지는 그림으로
			덮어 쓰는 방식..
		-------------------------

			-	장점..

				-	배경과 그려지는 그림이
					단순할 때는 적용 가능..

				
			-	단점..

				-	앞에 그림에 의해 배경의
					일부가 삭제 될수 있음..

	----------------
	-	더블 버퍼링..
	----------------

		-	버퍼를 2개 이상 사용..

			-	화면에 보여줄 버퍼..

			-	내부 작업에 사용할 버퍼..

				ㄴ	가상 화면..


		-	가상 화면에 미리 그림을 그린 후
			화면 버퍼로 고속 전송..

		-	그리는 중간 과정을
			가상 화면에서 처리함..

			-	사용자는 최종 결과만
				보는 기법..

		--------------
		-	가상 화면..
		--------------

			-	메모리 영역..

			-	외부 버퍼( 화면 )와
				호환 되어야함..

			-	윈도우즈에서는 비트맵으로
				가상화면 역할 가능..



	---------------------
	-	더블 버퍼링을 위한
		사전 작업..
	---------------------
	
		---------------------
		-	비트맵 활용하여
			가상 화면 만들기..
		---------------------

			--------------
			-	가상 화면..
			--------------

				-	모니터 상의 화면이 아닌
					메모리에 구현된 가짜 화면..
			
		
			---------------------
			-	가상 화면 만들기..
			---------------------

				1)	화면DC와 호환되는
					메모리DC를 생성..

				2)	메모리DC에 비트맵을 선택..

				3)	메모리DC가 가상 화면이 됨..



			----------
			-	특징..
			----------

				-	진짜 화면과 마찬가지로
					모든 그래픽을 출력가능..

					-	이때 출력은 화면이 아닌
						[ 메모리DC ]에 선택된
						[ 비트맵 ]으로 보내짐..


				-	비트맵이 모니터처럼
					그리기 표면이 됨..

					-	이때 사용되는 비트맵을
						[ OffScreen Bitmap ] 이라고 함..
	

			----------
			-	목적..
			----------

				-	그림을 그리는 중간과정을
					보여주지 않으므로
					화면을 갱신하는 과정에서
					화면의 깜빡거림이 사라짐..

				-	게임에 많이 활용됨..
