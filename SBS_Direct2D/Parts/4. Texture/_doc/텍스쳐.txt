			* 밉맵..

				-	정의..

					-	하나의 텍스쳐를 일정한 크기로 축소시켜서
						여러 장의 이미지를 가지고 있다가 
						현재 사이즈에 가장 적합한 이미지를
						찾아서 사용하는 방식...
						( 참고 : _ref / 원본 nvidia.jpg, 밉맵 nvidia.jpg )


				-	사용배경..

					-	커다란 물체( with 해상도가 큰 텍스쳐 )가
						카메라로부터 거리가 멀어져 작게 보이는 경우,
						무수한 텍셀( 3D 모델에 적용된 텍스쳐의 픽셀 )정보를
						계산 후, 단지 몇개의 픽셀만을 사용..

						->	비효율적..
							( 참고 : https://ozlael.tistory.com/tag/Mipmap )

				-	작동 방식..

						1)	원본 이미지의 크기를 확장..

						2)	남은 공간에 다양한 크기로
							축소된 이미지를 배치..

						3)	이중 적당한 텍스쳐를 골라 사용..


				-	주의 사항..

					-	밉맵을 사용하려면 텍스쳐의 크기가
						2의 지수형..( Power Of Two, POT )

						-	유니티는 텍스쳐의 크기가 POT가 아닌 경우,
							원본보다 큰 POT 사이즈로 메모리 상에서 변경..

							예) 1280 x 1280 -> 2048 x 2048

				
				-	텍스쳐 사이즈를 POT로 하는 이유..
					( 참고 : http://egloos.zum.com/chulin28ho/v/2594532 )


					1)	구형 그래픽 카드와의 호환..

						-	이전 그래픽 카드는 2의 승수
							크기 제한이 있었음..

							ㄴ	15년 이상 된 이슈이므로
								최근엔 무의미..


					2)	텍스쳐 어드레스 연산시
						시프트 연산으로 처리하므로
						이미지 처리가 빨라짐..

						-	시프트 연산..

							-	각 비트를 원하는 만큼 이동시킴..

							-	4 << 2
								->	0100 << 2
								->	0001 0000
								->	16	->	4 * 2의 2승..

								4 >> 2
								->	0100 >> 2
								->	0001
								->	1	->	4 / 2의 2승..
							
								*	2의 n승으로 연산!!

						-	2의 n승이 아니라면 이런 처리가 불가능하여
							더 복잡한 과정을 거치게 되므로
							성능저하의 원인이 됨..


					3)	2D 이미지의 깨끗한 처리..
						( 참고 : https://ordinarybk.tistory.com/entry/2D-Texture-%ED%81%AC%EA%B8%B0%EB%8A%94-2%EC%9D%98-n%EC%8A%B9%EC%9D%84-%EC%A7%80%EC%BC%9C%EC%95%BC-%ED%95%98%EB%8A%94%EA%B0%80 )

						-	UV 좌표..
							=	스프라이트의 X,Y 좌표 / 텍스쳐 크기..

							-	UV 좌표는 0.0 ~ 1.0 범위를 갖게 됨..
								( 부동 소수점 형식 )

							-	텍스쳐의 크기가 2의 승수가 아닌 경우..

								-	부동 소수점 오차가 발생할 가능성 증가..

								-	슬라이스 현상으로 인해 값이 잘리기도 함..

								-	정확한 UV 좌표를 설정할수 없으므로
									이미지가 약간 뭉게져서 나옴..
